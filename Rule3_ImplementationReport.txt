## Implementation Report: `Rule3` Static Analysis Rules

### 1. Rules Implemented

- **MISRA-3-1-1 — Header File Inclusion Without ODR Violations ([`Rule311`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule3/Rule311.cpp)):**
  - Inspects file- and namespace-scope `FunctionDecl` and `VarDecl` nodes whose spelling location resides in a project header file (`!sm.isInMainFile(spellingLoc)` or `.h`/`.hh`/`.hpp`/`.hxx` extension). Does not report declarations or definitions in non-header source files (`.cpp`).
  - Flags non-`inline`, non-`constexpr`, non-template function definitions in header files (`void F3() {}`) as well as non-`inline` `static` function declarations/definitions in header files (`static void F6() noexcept;`).
  - Flags non-`const`, non-`constexpr`, non-`inline` variable definitions in header files (`std::int32_t a;`, `static std::int32_t f;`), while allowing pure `extern` declarations (`extern std::int32_t b;`) and `const`/`constexpr` internal-linkage constants (`constexpr static`, `const static`).

- **MISRA-3-2-2 — One Definition Rule Token-Diff Detection ([`Rule322`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule3/Rule322.cpp)):**
  - First traverses the translation unit with `UsedEntityCollector` to record actively used tag types, called functions (including `main`), and referenced objects so unused code, uninstantiated templates, and uncalled functions are excluded.
  - Scans included project headers and main source files in inclusion order for `struct`/`class`/`union`/`enum` definitions as well as AST `FunctionDecl` and `VarDecl` definitions, extracting raw token sequences via `clang::Lexer`.
  - Flags subsequent definitions of the same used entity when their token sequences differ by at least one token (such as `struct Packet` in `Rule322.h` vs. `Rule322.cpp`), reporting at the closing brace location (`}; //Noncompliant`).

- **MISRA-3-2-3 — Single-File Declaration of External Objects ([`Rule323`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule3/Rule323.cpp)):**
  - Traverses file- and namespace-scope `VarDecl` nodes with explicit `extern` storage (`SC_Extern`, `DeclarationOnly`) across included project header files and source files.
  - Records the normalized file path of the first `extern` declaration for each qualified object name (`getQualifiedNameAsString()`) and flags any subsequent `extern` declaration of the same object that appears in a different file, while leaving objects declared in only one file unflagged.

- **MISRA-3-9-1 — Token-for-Token Identical Types Across Declarations ([`Rule391`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule3/Rule391.cpp)):**
  - Extracts the exact sequence of written type tokens from the source buffer using `clang::Lexer` for each `VarDecl` object type and each `FunctionDecl` return type and parameter type (retaining `typedef` names and `const`/`volatile` qualifiers while stripping storage-class and function specifiers such as `extern`, `static`, `inline`).
  - Compares each declaration or redeclaration against the last seen declaration of the same canonical entity (`getCanonicalDecl()`), reporting a violation whenever the object type, return type, or any parameter type is not token-for-token identical (e.g., `int* map;` followed by `extern intptr map;`).

### 5. Known Limitations

- **Same-TU Redefinition Diagnostics from Clang Frontend:** When a header and source file in the same translation unit define the same `struct` with conflicting member layouts (as in `Rule322.h` and `Rule322.cpp`), Clang's frontend parser emits a compiler diagnostic (`error: redefinition of 'Packet'`) while building the AST. `Rule322` supplements AST traversal with a raw lexer scan over the TU's project `FileID`s so that conflicting tag definitions are reliably tokenized and reported even when Clang's parser recovers from a redefinition error.
- **Per-Translation-Unit Evaluation:** Checkers evaluate declarations across each translation unit and its included project headers (`#include`), preventing false cross-contamination when unrelated test files are batch-scanned together.
