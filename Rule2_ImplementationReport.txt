## Implementation Report: `Rule2` Static Analysis Rules

### 1. Rules Implemented

- **MISRA-2-10-1 — Typographically Unambiguous Identifiers ([`Rule2101`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule2/Rule2101.cpp)):**
  - Traverses user-declared `NamedDecl` nodes (`VarDecl`, `FunctionDecl`, `FieldDecl`, `TypedefNameDecl`, `TagDecl`, `EnumConstantDecl`, `NamespaceDecl`) in project files (`.h` and `.cpp`), excluding implicit declarations, constructors, destructors, conversion operators, and overloaded operators.
  - Normalizes each identifier into a canonical typographic skeleton by removing underscores (`_`), folding ASCII letters to lowercase, collapsing `"rn"` into `"m"`, and mapping visually similar characters to single representatives (`{O, o, 0} -> 0`, `{I, i, l, 1} -> 1`, `{Z, z, 2} -> 2`, `{S, s, 5} -> 5`, `{B, b, 8} -> 8`).
  - Reports a violation when two distinct identifier strings (`rawName1 != rawName2`) normalize to the same canonical skeleton.

- **MISRA-2-10-2 — Identifier Hiding Across Nested Scopes ([`Rule2102`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule2/Rule2102.cpp)):**
  - Uses a `RecursiveASTVisitor` that maintains a stack of active lexical scopes across `TranslationUnitDecl`, `NamespaceDecl`, `RecordDecl`/`CXXRecordDecl`, `EnumDecl`, `FunctionDecl`/`CXXMethodDecl`, `CompoundStmt`, `ForStmt`, `CXXForRangeStmt`, `WhileStmt`, `IfStmt`, and `SwitchStmt`.
  - Checks each newly declared identifier against all strictly outer scopes on the stack, reporting when an inner-scope declaration hides an outer-scope identifier of the same name.
  - Excludes parameter names on bodiless function prototypes and out-of-line method redeclarations to prevent false positives across header/source splits.

- **MISRA-2-10-3 — Unique `typedef` Identifiers ([`Rule2103`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule2/Rule2103.cpp)):**
  - Computes the enclosing namespace qualification string for each declaration by walking parent `NamespaceDecl` contexts (so declarations in distinct namespaces such as `NS1::WIDTH` and `NS2::WIDTH` remain distinct, while local declarations in functions within the same namespace share the same enclosing namespace qualification).
  - Flags any subsequent declaration with a different canonical declaration that reuses a `TypedefNameDecl` identifier within the same namespace qualification.

- **MISRA-2-10-4 — Unique Class, Union, or Enum Identifiers ([`Rule2104`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule2/Rule2104.cpp)):**
  - Tracks user-declared `TagDecl` (`class`, `struct`, `union`, `enum`) identifiers qualified by their enclosing namespace hierarchy across project headers and source files.
  - Reports any declaration with a different canonical declaration that reuses a `TagDecl` identifier within the same namespace qualification across scopes.
  - Defers same-scope collisions between a `TagDecl` and a `VarDecl`/`FunctionDecl` (such as `struct vector { ... } vector;`) to `Rule2106` (`MISRA-2-10-6`).

- **MISRA-2-10-6 — Type vs. Object/Function Identifier in the Same Scope ([`Rule2106`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule2/Rule2106.cpp)):**
  - Groups declarations by `(DeclContext::getRedeclContext(), identifierName)` and tracks whether each identifier in a scope refers to a type (`TagDecl`, `TypedefNameDecl`) and/or an object or function (`VarDecl`, `FunctionDecl`, `FieldDecl`).
  - Deduplicates declarations by `getCanonicalDecl()` so functions or types that are both declared and defined in the same scope are reported only once.
  - Reports the violation at the identifier token location (`d->getLocation()`) so inline variable definitions following a struct definition (`}vector; //Noncompliant`) are reported on the exact offending line.

### 5. Known Limitations

- **Per-Translation-Unit Traversal:** `Rule2101`, `Rule2102`, `Rule2103`, `Rule2104`, and `Rule2106` analyze each translation unit (including all transitively `#include`d project `.h` files filtered by `ProjectFileFilter`). Identifiers declared across completely unrelated `.cpp` files that do not share a header are evaluated independently within their respective translation units, preventing cross-test interference when scanning test directories.
- **Preprocessor Macros:** Checks operate on Clang AST `NamedDecl` nodes after preprocessing; macro names `#define`d and consumed before AST construction are not inspected as AST declarations.
