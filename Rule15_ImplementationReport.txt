## Implementation Report: `Rule15` Static Analysis Rules

### 1. Rules Implemented

- **MISRA-15-3-5 — Class Type Exceptions Shall Be Caught by Reference ([`Rule1535`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule15/Rule1535.cpp)):**
  - Matches `CXXCatchStmt` AST nodes (`cxxCatchStmt()`) and inspects `catchStmt->getCaughtType()`, ignoring `catch (...)` ellipsis handlers where `getCaughtType().isNull()`.
  - Resolves typedefs and type aliases via `caughtType.getCanonicalType()` and handles both named and unnamed catch parameters (`catchStmt->getCatchLoc()`).
  - Treats reference types (`canonType->isReferenceType()`, covering both `T&` and `const T&`) and non-class types (primitives, pointers, enums) as compliant, and flags handlers where the canonical caught type is a class/struct/union by value (`!canonType->isReferenceType() && canonType->isRecordType()`).

- **MISRA-15-3-6 — Exception Handlers Ordered from Most-Derived to Base Class ([`Rule1536`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule15/Rule1536.cpp)):**
  - Matches `CXXTryStmt` AST nodes (`cxxTryStmt()`), covering both regular `try-catch` statements and function-try-blocks with two or more handlers (`tryStmt->getNumHandlers() >= 2`).
  - Extracts the canonical `CXXRecordDecl` definition (`getCaughtClassDecl`) for each handler's caught type after unwrapping reference (`T&`, `const T&`) and pointer qualifiers.
  - Compares each handler `i` against all preceding handlers `j < i` within the same `CXXTryStmt` using Clang's class inheritance hierarchy (`currClass->isDerivedFrom(prevClass)` or identical canonical class declarations), flagging any derived-class handler that follows a direct or indirect base-class handler at most once per offending handler.

- **MISRA-15-3-7 — Ellipsis (`catch-all`) Handler Shall Occur Last ([`Rule1537`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule15/Rule1537.cpp)):**
  - Inspects `CXXTryStmt` AST nodes (`cxxTryStmt()`) and also performs a recursive-descent token-stream scan (`TryCatchTokenScanner` via `clang::Lexer`) across project files in the translation unit.
  - Because C++ compilers (including Clang's frontend parser) reject `catch` clauses that follow `catch (...)` with `error: catch-all handler must come last` and omit the trailing handler from the `CXXTryStmt` AST node, `TryCatchTokenScanner` parses balanced `try { ... } catch (...) { ... }` blocks and nested `try-catch` scopes independently and flags any handler appearing after `catch (...)` within the same `try-catch` statement or function-try-block.

- **MISRA-15-5-1 — Class Destructors Shall Not Exit with an Exception ([`Rule1551`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule15/Rule1551.cpp)):**
  - Matches `CXXDestructorDecl` definitions (`cxxDestructorDecl(isDefinition())`, excluding implicit destructors and uninstantiated templates) and traverses the destructor body with `DestructorThrowVisitor`.
  - Flags explicit `CXXThrowExpr` statements (both throwing new exceptions and rethrowing via `throw;`) occurring directly in the destructor's execution scope.
  - Enforces all specified exclusions and intentional checker limitations:
    1. Does not perform interprocedural analysis on functions called by the destructor.
    2. Treats the presence of any `catch` statement on a `try` block (`tryStmt->getNumHandlers() > 0`) as sufficient indication that exceptions in that `try` block are caught (`TraverseCXXTryStmt` skips `try-catch` subtrees).
    3. Does not flag `throw` statements inside `catch` blocks (`TraverseCXXCatchStmt` skips `catch` subtrees).
    4. Excludes `throw` statements inside nested `LambdaExpr`, local `CXXRecordDecl`, or nested `FunctionDecl` scopes.

### 5. Known Limitations

- **Intentional Rule 15-5-1 Specification Exclusions:** By explicit specification, `Rule1551` does not perform interprocedural exception analysis on functions called from a destructor, treats any `try-catch` block inside a destructor as catching exceptions thrown within its `try` block regardless of caught types, and does not flag `throw` statements inside `catch` blocks or nested callable scopes (`LambdaExpr`, local classes).
- **Frontend Parse Error in [Rule1537.cpp](file:///c:/Users/HanLo/Projects/misra/tests/Rule15/Rule1537.cpp):** Because `catch (...)` followed by another `catch` handler is ill-formed in C++ (and `Rule1537.cpp` also contains an extra closing brace on line 33), Clang emits frontend diagnostics during parsing; `Rule1537` uses `TryCatchTokenScanner` via `clang::Lexer` so the noncompliant handler on line 28 is reliably detected without modifying the test fixture.
