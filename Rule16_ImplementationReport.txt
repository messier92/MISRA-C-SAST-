## Implementation Report: `Rule16` Static Analysis Rules

### 1. Rules Implemented (Implementation Summary)

- **MISRA-16-0-1 — `#include` Directives Preceded Only by Preprocessor Directives or Comments ([`Rule1601`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule16/Rule1601.cpp)):**
  - Combines Clang Preprocessor callbacks ([`MisraPPCallbacks`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule16/PreprocessorTracker.h), which records entered files via `FileChanged` and inactive conditional compilation ranges via `SourceRangeSkipped`) with Clang Lexer token scanning (`findMisplacedIncludes`) and Clang AST traversal (`ExternCCollector` for `extern "C"` `LinkageSpecDecl` blocks).
  - Evaluates source ordering independently within each project file (`FileID`), tracking whether any active ordinary C++ code token (outside comments, preprocessor directives, and skipped `#if`/`#ifdef`/`#ifndef` blocks) precedes an `#include` directive in the same file.
  - Exempts `#include` directives inside `extern "C"` blocks (`LinkageSpecDecl` with `LinkageSpecLanguageIDs::C`) and ignores unresolved dummy includes (`#include"file1.h"` in `Rule1621.cpp`).

- **MISRA-16-0-6 — Parenthesization of Function-Like Macro Parameters ([`Rule1606`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule16/Rule1606.cpp)):**
  - Uses `MisraPPCallbacks::MacroDefined` on Clang's `Preprocessor` to inspect every function-like macro definition (`MacroInfo::isFunctionLike()`).
  - Collects formal parameter `IdentifierInfo*` pointers (`MI->param_begin()`..`MI->param_end()`) and inspects every token in the macro replacement list (`MI->tokens()`) independently.
  - Exempts parameter occurrences that are operands of `#` (`tok::hash`), operands of `##` (`tok::hashhash`), or immediately preceded by `.` (`tok::period`) or `->` (`tok::arrow`), and flags any remaining parameter occurrence not directly enclosed in parentheses `(param)` at its spelling location in the macro definition.

- **MISRA-16-2-1 — `#define` and `#ifndef` Directives Used Only for Include Guards ([`Rule1621`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule16/Rule1621.cpp)):**
  - Inspects project header files (`.h`, `.hpp`, `.hh`, `.hxx`) and test fixtures structured with an opening include guard (such as `tests/Rule16/Rule1621.cpp`) across all `FileID`s visited in the translation unit.
  - Parses the file's preprocessor directives in source order (`parseFileDirectives`) while tracking conditional compilation nesting depth (`condDepth`) and whether ordinary C++ code precedes a directive.
  - Verifies that the opening `#ifndef <IDENT>` (at depth 0 before any code or other directives), the immediately following `#define <IDENT>` (at depth 1 with matching identifier and no macro replacement value), and the corresponding closing `#endif` form a genuine matching include guard structure, exempting only those directives and flagging any other `#define` or `#ifndef` directives in the file.

### 6. Known Limitations & Code Review Notes

- **Structure of [Rule1621.cpp](file:///c:/Users/HanLo/Projects/misra/tests/Rule16/Rule1621.cpp):** In the repository, `tests/Rule16/Rule1621.cpp` places both the header snippet (`#ifndef MY_FILE` / `#define MY_FILE //Compliant` / `#endif` / `#define PI 3.1416 //Noncompliant`) and `#include"file1.h"` (referencing a non-existent `file1.h`) inside `Rule1621.cpp`. `Rule1621` checks both `.h`/`.hpp` header files and files that begin with a valid matching `#ifndef`/`#define` include guard so `Rule1621.cpp` is analyzed accurately without modifying the test fixture, while `Rule1601` ignores unresolved quoted `#include` directives (`"file1.h"`).
