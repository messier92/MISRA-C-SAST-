# `misra_checker` — MISRA C++:2008 Static Analysis Tool

## 1. Overview & Purpose

`misra_checker` is a command-line static analysis tool that checks C++ source code against **36 MISRA C++:2008 coding guidelines** across 9 rule groups (`Rule 0`, `Rule 2`, `Rule 3`, `Rule 5`, `Rule 6`, `Rule 7`, `Rule 9`, `Rule 15`, and `Rule 16`).

Built on **Clang LibTooling** (`LLVM/Clang 18.1.8`), it parses translation units with the Clang C++ frontend, inspects the resulting Clang AST, CFG, and Preprocessor token streams (`PPCallbacks` / `Lexer`), and produces a consolidated compliance report.

### Core Capabilities
- **Flexible Input:** Analyze a single `.cpp` file, an entire C++ repository directory (recursive `.cpp`/`.c`/`.cc`/`.cxx` discovery), or a CMake `compile_commands.json` compilation database.
- **Three Analysis Tiers:**
  1. **Preprocessor-level (`PPCallbacks` & `Lexer`):** Inspects `#include` ordering, conditional compilation (`#if`/`#ifdef`/`#ifndef`), header include guards, and function-like macro parameter parenthesization.
  2. **Translation-Unit AST & CFG level:** Runs Clang `ASTMatchers`, `RecursiveASTVisitor`s, and Clang control-flow graphs (`clang::CFG`) on each translation unit.
  3. **Project-wide Cross-TU level (`GlobalSymbolDatabase`):** Aggregates plain-value symbol declarations, definitions, and uses across all translation units to detect One Definition Rule (ODR), unused variable/field, and cross-file type consistency violations.
- **Deterministic Precedence Resolution:** Resolves same-line multi-rule conflicts using the project's rule group precedence hierarchy and outputs both console diagnostics and a formatted report file (`misra_output.txt` by default).

## 2. Build & Environment

- **Platform:** Windows, Visual Studio 2022 (MSVC), C++17, CMake $\ge$ 3.20.
- **Primary Dependency:** LLVM/Clang 18.1.8 built in `Release` mode (`C:/Program Files/llvm-project/build`).
- **Linked Libraries:** `clangTooling`, `clangASTMatchers`, `clangFrontend`, `clangSerialization`, `clangDriver`, `clangParse`, `clangSema`, `clangAnalysis`, `clangEdit`, `clangAST`, `clangLex`, `clangBasic`, `clangRewrite`, LLVM `Core`/`Support`/`Option`, and Windows system libraries (`version.lib`, `advapi32.lib`, `shell32.lib`, `ole32.lib`).
- **Output Binary:** `build\Release\Release\misra_checker.exe`

### Building from Source

```powershell
# 1. Configure CMake (if not already configured)
cmake -B build -S .

# 2. Build the Release executable and unit tests
cmake --build build --config Release

# 3. Run unit tests (ViolationStore precedence verification)
ctest --test-dir build -C Release --output-on-failure
```

## 3. Running `misra_checker.exe` on Any C++ Repository

### Command-Line Syntax

```text
misra_checker.exe [options] <source-path-or-directory>... [-- <compiler-flags>...]
```

| Option | Description |
| :--- | :--- |
| `<source-path-or-directory>` | One or more `.cpp`/`.cc`/`.cxx`/`.c` files, or a directory path (automatically expanded recursively to all C/C++ source files inside it). |
| `--project-root=<path>` | Root directory of the target repository. Filters out diagnostics from third-party libraries or headers outside `<path>`. Defaults to the target directory (or parent directory of the first source file). |
| `--output=<file>` | Path to write the analysis report file (default: `misra_output.txt`). |
| `-p <build-dir>` | Path to a directory containing `compile_commands.json` (generated by CMake with `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`). |
| `-- <compiler-flags>...` | Compiler flags passed directly to the Clang frontend (e.g., `-std=c++17`, `-I<include-dir>`, `-D<MACRO>=<VAL>`). Use `--` when no `compile_commands.json` is present. |

---

### Usage Scenarios for Any C++ Repository

#### Scenario A: Scan an Entire C++ Repository Directory (No `compile_commands.json` Required)
Point `misra_checker.exe` directly at the repository root (or its `src/` folder) and pass `-- -std=c++17` plus any `-I` include directories used by the repository:

```powershell
.\build\Release\Release\misra_checker.exe C:\path\to\my_cpp_repo `
    --project-root=C:\path\to\my_cpp_repo `
    --output=C:\path\to\my_cpp_repo\misra_report.txt `
    -- -std=c++17 -IC:\path\to\my_cpp_repo\include -IC:\path\to\my_cpp_repo\src
```

#### Scenario B: Scan a CMake Repository Using `compile_commands.json`
If the target C++ repository uses CMake (with Ninja or Makefile generators, or Clang-cl), export `compile_commands.json` so `misra_checker.exe` automatically uses the exact per-target include paths and preprocessor definitions:

```powershell
# 1. Generate compile_commands.json in the target repository
cmake -B C:\path\to\my_cpp_repo\build -S C:\path\to\my_cpp_repo -DCMAKE_EXPORT_COMPILE_COMMANDS=ON

# 2. Run misra_checker.exe using -p <build-dir>
.\build\Release\Release\misra_checker.exe C:\path\to\my_cpp_repo\src `
    -p C:\path\to\my_cpp_repo\build `
    --project-root=C:\path\to\my_cpp_repo `
    --output=misra_report.txt
```

#### Scenario C: Scan Specific Files or Built-In Test Suites
```powershell
# Run against a single test suite directory
.\build\Release\Release\misra_checker.exe tests\Rule0 -- -std=c++17
.\build\Release\Release\misra_checker.exe tests\Rule2 -- -std=c++17
.\build\Release\Release\misra_checker.exe tests\Rule3 -- -std=c++17
.\build\Release\Release\misra_checker.exe tests\Rule5 -- -std=c++17
.\build\Release\Release\misra_checker.exe tests\Rule6 -- -std=c++17
.\build\Release\Release\misra_checker.exe tests\Rule7 -- -std=c++17
.\build\Release\Release\misra_checker.exe tests\Rule9 -- -std=c++17
.\build\Release\Release\misra_checker.exe tests\Rule15 -- -std=c++17
.\build\Release\Release\misra_checker.exe tests\Rule16 -- -std=c++17

# Run against a single source file
.\build\Release\Release\misra_checker.exe tests\Rule7\Rule711.cpp -- -std=c++17

# Run against the entire tests/ directory at once
.\build\Release\Release\misra_checker.exe tests -- -std=c++17
```

> **Exit Code:** `misra_checker.exe` returns `0` when zero violations are found, and `1` when one or more MISRA violations are reported (making it ready for CI/CD pipelines).

## 4. Architecture & Data Flow

```text
argv (directory / files / -p compile_commands.json)
  └─ main() [src/main.cpp]:
       ├─ Parses CLI options (--project-root, --output) & discovers .cpp/.c/.cc/.cxx files
       ├─ Initializes shared ViolationStore and GlobalSymbolDatabase
       ├─ Instantiates and registers all 36 Rule checkers
       └─ Runs ClangTool over every translation unit:
            └─ MisraChecker (ASTFrontendAction) [src/MisraChecker.cpp]
                 └─ CreateASTConsumer(ci, file):
                      ├─ Attaches MisraPPCallbacks (Rule 16 preprocessor tracking)
                      └─ Returns MisraConsumer
                           └─ HandleTranslationUnit(ctx):
                                └─ For each Rule:
                                     ├─ Injects store_, db_, ctx_
                                     ├─ rule->registerMatchers(finder)
                                     └─ finder.matchAST(ctx)
                                          ├─ File-level rules    → Rule::report() → ViolationStore
                                          └─ Project-level rules → GlobalSymbolDatabase::record*()
  └─ Post-TU Project Evaluation [src/main.cpp]:
       ├─ db.evaluateAll(store)  (evaluates cross-TU rules 0-1-3, 3-2-2, 3-2-3, 3-9-1)
       └─ store.finalize(outputPath):
            ├─ ViolationStore::applyPrecedence() (resolves same-line conflicts)
            └─ Prints report to stdout and writes misra_output.txt
```

## 6. Implemented MISRA C++:2008 Rules (36 Rules)

| Group | Rule ID | MISRA C++:2008 Rule Description | Scope |
| :--- | :--- | :--- | :--- |
| **Rule 0** | `MISRA-0-1-1` | A project shall not contain unreachable code. | TU / CFG |
| | `MISRA-0-1-3` | A project shall not contain unused variables. | Project + TU |
| | `MISRA-0-1-6` | A project shall not contain instances of non-volatile variables being given values that are never subsequently used. | TU / CFG |
| | `MISRA-0-1-7` | The value returned by a function having a non-void return type that is not an overloaded operator shall always be used. | TU / AST |
| | `MISRA-0-1-8` | All functions with void return type shall have external side effect(s). | TU / AST |
| | `MISRA-0-1-9` | There shall be no dead code. | TU / CFG |
| **Rule 2** | `MISRA-2-10-1` | Different identifiers shall be typographically unambiguous. | TU / AST |
| | `MISRA-2-10-2` | Identifiers declared in an inner scope shall not hide an identifier declared in an outer scope. | TU / AST |
| | `MISRA-2-10-3` | A typedef name (including qualification, if any) shall be a unique identifier. | TU / AST |
| | `MISRA-2-10-4` | A class, union or enum name (including qualification, if any) shall be a unique identifier. | TU / AST |
| | `MISRA-2-10-6` | If an identifier refers to a type, it shall not also refer to an object or a function in the same scope. | TU / AST |
| **Rule 3** | `MISRA-3-1-1` | It shall be possible to include any header file in multiple translation units without violating the One Definition Rule. | Header / AST |
| | `MISRA-3-2-2` | The One Definition Rule shall not be violated. | Project + TU |
| | `MISRA-3-2-3` | A type, object or function that is used in multiple translation units shall be declared in one and only one file. | Project + TU |
| | `MISRA-3-9-1` | The types used for an object, a function return type, or a function parameter shall be token-for-token identical in all declarations and re-declarations. | Project + TU |
| **Rule 5** | `MISRA-5-0-4` | An implicit integral conversion shall not change the signedness of the underlying type. | TU / AST |
| | `MISRA-5-0-6` | An implicit integral or floating-point conversion shall not reduce the size of the underlying type. | TU / AST |
| | `MISRA-5-0-8` | An explicit integral or floating-point conversion shall not increase the size of the underlying type of a cvalue expression. | TU / AST |
| | `MISRA-5-2-4` | C-style casts (other than void casts) and functional notation casts (other than explicit constructor calls) shall not be used. | TU / AST |
| | `MISRA-5-3-1` | Each operand of the `!` operator, the logical `&&` or the logical `\|\|` operators shall have type `bool`. | TU / AST |
| **Rule 6** | `MISRA-6-2-1` | Assignment operators shall not be used in sub-expressions. | TU / AST |
| | `MISRA-6-4-5` | An unconditional `throw` or `break` statement shall terminate every non-empty switch-clause. | TU / AST |
| | `MISRA-6-5-1` | A `for` loop shall contain a single loop-counter which shall not have floating type. | TU / AST |
| | `MISRA-6-6-5` | A function shall have a single point of exit at the end of the function. | TU / AST |
| **Rule 7** | `MISRA-7-1-1` | A variable which is not modified shall be `const` qualified. | TU / AST |
| | `MISRA-7-3-1` | The global namespace shall only contain `main`, namespace declarations and `extern "C"` declarations. | TU / AST |
| **Rule 9** | `MISRA-9-3-1` | `const` member functions shall not return non-`const` pointers or references to class-data. | TU / AST |
| | `MISRA-9-3-3` | If a member function can be made `static` then it shall be made `static`, otherwise if it can be made `const` then it shall be made `const`. | TU / AST |
| | `MISRA-9-5-1` | Unions shall not be used. | TU / AST |
| **Rule 15** | `MISRA-15-3-5` | A class type exception shall always be caught by reference. | TU / AST |
| | `MISRA-15-3-6` | Where multiple handlers are provided in a single `try-catch` statement or function-try-block for a derived class and some or all of its bases, the handlers shall be ordered most-derived to base class. | TU / AST |
| | `MISRA-15-3-7` | Where multiple handlers are provided in a single `try-catch` statement or function-try-block, any ellipsis (catch-all) handler shall occur last. | TU / Lexer + AST |
| | `MISRA-15-5-1` | A class destructor shall not exit with an exception. | TU / AST |
| **Rule 16** | `MISRA-16-0-1` | `#include` directives in a file shall only be preceded by other preprocessor directives or comments. | Preprocessor + AST |
| | `MISRA-16-0-6` | In the definition of a function-like macro, each instance of a parameter shall be enclosed in parentheses, unless it is used as the operand of `#` or `##`. | Preprocessor |
| | `MISRA-16-2-1` | The preprocessor shall only be used for file inclusion and include guards. | Preprocessor |

### Same-Line Reporting Precedence

When multiple rules flag the same `(file, line)`, `ViolationStore::applyPrecedence()` selects the winning violation according to the following rule group priority (highest to lowest):

1. **Rule 15**
2. **Rule 5**
3. **Rule 3**
4. **Rule 16**
5. **Rule 7**
6. **Rule 9**
7. **Rule 2**
8. **Rule 6**
9. **Rule 0**

*Exception:* Any **Rule 0-1-x** violation takes precedence over **Rule 6-6-5** on the same line.
