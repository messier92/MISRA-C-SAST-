## Implementation Report: `Rule5` Static Analysis Rules

### 1. Rules Implemented

- **MISRA-5-0-4 — Implicit Integral Conversions Changing Signedness ([`Rule504`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule5/Rule504.cpp)):**
  - Evaluates the MISRA C++:2008 *underlying type* of expressions (`getUnderlyingType`) prior to standard C++ integral promotions to `int`, unwrapping parentheses and implicit casts while preserving explicit casts (`ExplicitCastExpr`) as their target type.
  - Treats `ptrdiff_t` (`std::ptrdiff_t`) as a signed integer type and inspects the canonical integer signedness of non-boolean, non-enum integer types.
  - Flags implicit integral conversions that change signedness (signed-to-unsigned or unsigned-to-signed) in assignments (`s8 = u8;`), binary arithmetic/bitwise/comparison operations (`u8 = s8 + u8;`), and variable initializations, while allowing explicit casts (`u8 = static_cast<uint8_t>(s8) + u8;`).
  - Takes reporting precedence over `MISRA-5-0-6` when an implicit integral conversion both reduces bit width and changes signedness.

- **MISRA-5-0-6 — Implicit Conversions Reducing Underlying Type Size ([`Rule506`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule5/Rule506.cpp)):**
  - Computes source and destination underlying type bit widths (`ASTContext::getTypeSize`) for non-boolean integral and floating-point expressions across assignments (`s16 = s32;`), variable initializations, and function call arguments.
  - Flags implicit conversions where `dstSize < srcSize` while excluding explicit casts (`s16 = static_cast<int16_t>(s32);`) and scalar literals.
  - Enforces the `Rule 5-0-4` over `Rule 5-0-6` precedence rule: if both source and destination are integer types with differing signedness, `Rule506` suppresses its diagnostic so only `MISRA-5-0-4` is reported.

- **MISRA-5-0-8 — Explicit Conversions Widening a `cvalue` Expression ([`Rule508`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule5/Rule508.cpp)):**
  - Matches `ExplicitCastExpr` nodes casting to non-boolean integral or floating-point types.
  - Unwraps parentheses and implicit conversions from the cast sub-expression and checks whether it is a complex *cvalue expression* (`BinaryOperator` arithmetic/bitwise/shift, `UnaryOperator` arithmetic/bitwise, or `ConditionalOperator`).
  - Computes the pre-promotion underlying type of the cvalue expression (e.g., `short` for `op1 + op2` where `op1` and `op2` are `short`) and flags the cast when `ctx.getTypeSize(dstType) > ctx.getTypeSize(srcUnderlying)` (`static_cast<int>(op1 + op2)`), while leaving casts applied directly to individual variable lvalues (`static_cast<int>(op1) + op2`) unflagged.

- **MISRA-5-2-4 — C-Style and Functional Notation Casts ([`Rule524`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule5/Rule524.cpp)):**
  - Matches `CStyleCastExpr` and `CXXFunctionalCastExpr` nodes in project files.
  - Flags all non-`void` C-style casts (`(Base*)(&obj)`, `(std::int32_t)var1`, `(float)var3`, `(std::int32_t)f`).
  - Flags parenthesized functional notation casts to scalar/pointer types while permitting casts to `void`, brace-enclosed uniform initializations (`Base{10}`, `std::uint32_t{0}`), and explicit constructor calls on record types (`CXXConstructExpr`, `CK_ConstructorConversion`).

- **MISRA-5-3-1 — Boolean Operands for `!`, `&&`, and `||` ([`Rule531`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule5/Rule531.cpp)):**
  - Matches logical negation (`UnaryOperator` `!`) and logical conjunction/disjunction (`BinaryOperator` `&&`, `||`).
  - Unwraps parentheses, temporary wrappers, and implicit boolean conversions (`IgnoreParenImpCasts()`) on each operand to inspect the operand's true pre-conversion type.
  - Flags `!`, `&&`, and `||` expressions at the operator location (`getOperatorLoc()`) when any operand does not have type `bool` (such as `checkPair(&athirdPair)` returning `int32_t`), while allowing comparison operators (`==`, `<`) and overloaded `bool operator==` calls.

### 5. Known Limitations

- **Constant Literals in Implicit Conversions:** Non-negative integer literals (e.g., `0`, `20`) have type `int` in C++ AST; `Rule504` and `Rule506` exclude raw scalar literals so standard constant initializations such as `std::int16_t var1 = 20;` in `Rule524.cpp` are not flagged as narrowing conversions from `int`.
- **Uninstantiated Templates:** Dependent expressions inside uninstantiated templates do not have concrete resolved bit widths or signedness and are skipped until instantiated.
