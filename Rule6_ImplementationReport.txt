## Implementation Report: `Rule6` Static Analysis Rules

### 1. Rules Implemented

- **MISRA-6-2-1 — Assignment Operators in Sub-Expressions ([`Rule621`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule6/Rule621.cpp)):**
  - Traverses the translation unit AST with a parent map (`ParentBuilder`) and inspects both built-in assignment operators (`BinaryOperator::isAssignmentOp()`, covering `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`) and overloaded assignment operator calls (`CXXOperatorCallExpr::isAssignmentOp()`).
  - Unwraps transparent AST wrapper nodes (`ExprWithCleanups`, `ImplicitCastExpr`, `CXXBindTemporaryExpr`, `MaterializeTemporaryExpr`, `ParenExpr`) and top-level comma expression chains (`BO_Comma`) to locate the enclosing statement or expression.
  - Permits assignments only when used as standalone expression statements (`CompoundStmt` child, `ForStmt` init or increment clause, `IfStmt`/`WhileStmt`/`DoStmt` body statement, `SwitchCase` body, or `LabelStmt` body) and flags assignments embedded in conditions (`if ((x = y) == 0)`), logical/relational/arithmetic expressions, function arguments, or return expressions.

- **MISRA-6-4-5 — Unconditional `throw` or `break` Terminating Switch Clauses ([`Rule645`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule6/Rule645.cpp)):**
  - Matches `SwitchStmt` nodes in project files and partitions the `CompoundStmt` switch body into clauses bounded by `SwitchCase` (`CaseStmt` and `DefaultStmt`) labels, unwrapping consecutive chained labels (`case 0: case 1:`).
  - Allows empty switch clauses (`case` labels with no statements prior to the next label) as compliant fall-through groupings.
  - Verifies via `terminatesWithBreakOrThrow` that every non-empty `case` or `default` clause ends with an unconditional `BreakStmt`, `CXXThrowExpr`, a `CompoundStmt` whose final non-null statement terminates with `break`/`throw`, or an `IfStmt` with both `then` and `else` branches terminating with `break`/`throw` (without counting `break` statements inside nested loops or nested switches).

- **MISRA-6-5-1 — Single Non-Floating Loop Counter in `for` Loops ([`Rule651`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule6/Rule651.cpp)):**
  - Inspects `ForStmt` nodes using `InitVarCollector`, `CondVarCollector`, and `ModifiedVarCollector` to track variables declared/initialized in `init`, referenced in `cond`, and modified in `inc` (via `++`, `--`, or assignment operators).
  - Flags `for` loops that declare or initialize multiple variables in `init`, use a floating-point loop variable (`float`, `double`, `long double`), modify zero or multiple distinct variables in `inc` (such as `for (int i = 0; i >= x; i = x++)` which modifies both `i` and `x`), or modify a variable in `inc` that does not match the loop counter in `init`/`cond`.
  - Includes a `clang::Lexer`-based fallback (`scanInvalidFunctionForLoops`) for functions marked `isInvalidDecl()` due to duplicate `int main()` definitions in the same translation unit (as in `tests/Rule6/Rule651.cpp`), ensuring floating-point loop counters in unparsed function bodies are also accurately reported.

- **MISRA-6-6-5 — Single Point of Exit at the End of a Function ([`Rule665`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule6/Rule665.cpp)):**
  - Collects all `ReturnStmt` nodes belonging to a `FunctionDecl` body via `FunctionReturnCollector` while stopping at nested `LambdaExpr` and `CXXRecordDecl` boundaries so returns in nested lambdas or local classes are evaluated separately.
  - Flags functions with more than one `ReturnStmt`, and non-`void` functions with a single `ReturnStmt` that is not the final top-level statement of the function body.
  - Reports early top-level returns followed by unreachable trailing statements at the trailing statement line so `ViolationStore`'s `Rule 0-1-x` over `Rule 6-6-5` precedence exception properly resolves same-line conflicts (e.g. `tests/Rule0/Rule011.cpp` line 19).

### 5. Known Limitations

- **Duplicate `int main()` in [Rule651.cpp](file:///c:/Users/HanLo/Projects/misra/tests/Rule6/Rule651.cpp):** `tests/Rule6/Rule651.cpp` defines `int main()` twice in the same translation unit (at line 17 and line 28). Clang emits a frontend diagnostic (`error: redefinition of 'main'`) on the second definition and skips parsing its body into the AST; `Rule651` handles this via a `clang::Lexer` fallback on invalid `FunctionDecl` nodes so line 30 is still analyzed without modifying the test fixture.

In accordance with project constraints, the test file was not modified.
