## Implementation Report: `Rule0` Static Analysis Rules

### 1. Rules Implemented

- **MISRA-0-1-1 — Unreachable Code ([`Rule011`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule0/Rule011.cpp)):**
  - Traverses function definitions top-down to detect statements following unconditional control-flow terminators (`return`, `break`, `continue`, `throw`, `goto`, `if`/`else` where both branches terminate, and infinite loops without `break`).
  - Detects executable statements in a `switch` body before the first `case`, `default`, or label statement.
  - Resets reachability when encountering labels (`CaseStmt`, `DefaultStmt`, `LabelStmt`) and unwraps labeled sub-statements.
  - Evaluates constant boolean conditions (`EvaluateAsBooleanCondition`) in `if`, `while`, and `for` statements to flag unreachable branches and loop bodies.
  - Updated [`Rule::isReachable`](file:///c:/Users/HanLo/Projects/misra/src/Rule.cpp#L101-L171) so other rules accurately skip unreachable code.

- **MISRA-0-1-3 — Unused Variables ([`Rule013`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule0/Rule013.cpp)):**
  - Inspects `VarDecl` (local and global variables, excluding `ParmVarDecl`, `volatile`, and `extern` non-definitions) and `FieldDecl` (struct/class member variables, excluding unnamed bit-field padding such as `unsigned char : 1`).
  - Tracks variable references and member accesses (`MemberExpr`) across active/reachable functions and methods in the translation unit (ignoring uncalled inline getters when the class is otherwise exercised in the TU, and distinguishing constructor member-initializer lists from live field reads/writes).
  - Leaves local/file-static variables with explicit value initializations to `Rule016` so unused initializations are not double-reported.

- **MISRA-0-1-6 — Unused Assignments ([`Rule016`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule0/Rule016.cpp)):**
  - Reports non-volatile local variables and file-scope `static` (or non-`extern` `const`) variables initialized with a value that is never subsequently read (respecting the specification's exception when an initialized variable is later overwritten by an assignment).
  - Builds a Clang `CFG` per function and performs forward reachability over `CFGBlock`s (including loop back-edges, so assignments used in subsequent loop iterations are not flagged) to detect value assignments overwritten by another assignment before any subsequent read.

- **MISRA-0-1-7 — Ignored Return Values ([`Rule017`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule0/Rule017.cpp)):**
  - Matches non-operator `CallExpr` nodes returning non-`void` types.
  - Walks up `ASTContext::getParents` through transparent wrappers (`ExprWithCleanups`, `MaterializeTemporaryExpr`, `CXXBindTemporaryExpr`, `ImplicitCastExpr`, `ParenExpr`) to detect calls whose results are discarded in expression statements or the LHS of a comma operator.
  - Allows explicit casts to `void` (`(void)fn()`, `static_cast<void>(fn())`), overloaded operators (`CXXOperatorCallExpr`), and the standard C string/memory functions (`memcpy`, `memset`, `memmove`, `strcpy`, `strncpy`, `strcat`, `strncat`).

- **MISRA-0-1-8 — Side-Effect-Free Functions ([`Rule018`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule0/Rule018.cpp)):**
  - Checks `void`-returning function definitions (excluding constructors, destructors, `main`, placement `new`/`delete`, lambdas, and empty `virtual` methods).
  - Recursively inspects the function body and any in-TU callees for external side effects: modifying or dereferencing pointer/reference parameters or non-local variables, accessing `this` or non-local/parameter struct/class members, accessing `volatile` objects, throwing exceptions (`CXXThrowExpr`), dynamic allocation (`new`/`delete`), inline assembly (`AsmStmt`), or calling impure functions other than the function itself (recognizing standard pure `<cmath>`/`<cstring>` functions).

- **MISRA-0-1-9 — Dead Operations ([`Rule019`](file:///c:/Users/HanLo/Projects/misra/src/rules/Rule0/Rule019.cpp)):**
  - Uses Clang `CFG` reachability to detect reachable standalone assignment statements (`res = 0;`) to non-aliased, non-volatile local variables where the RHS has no side effects and the assigned value reaches function exit without ever being read (and without duplicating overwritten-assignment diagnostics from `Rule016`).
  - Also detects reachable standalone side-effect-free expression statements whose computed values are discarded.

### 5. Known Limitations

- **Cross-TU purity and usage analysis:** `Rule013`, `Rule016`, `Rule018`, and `Rule019` operate per translation unit. In `Rule018`, external functions without a body in the current translation unit (and not in the known-pure standard library list or annotated with `pure`/`const` attributes) are conservatively assumed to have side effects to avoid false positives.
- **Pointer aliasing in `Rule016` and `Rule019`:** Local variables whose addresses are taken (`&var`) or bound to references are conservatively treated as aliased so indirect reads/writes through pointers do not trigger false dead-assignment diagnostics.
